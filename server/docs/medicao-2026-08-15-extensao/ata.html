DATA: 12/08/2026

TÓPICO: Atraso na integracao e readequacao do cronograma do Projeto Fenix

ANDAMENTO: A integracao com a API de faturamento do cliente travou devido a documentacao desatualizada e foi identificada lentidao na consulta de fechamento mensal. O cronograma foi reajustado com a adiamento da entrega para 28 de agosto de 2026, com definicoes sobre criacao de indice no banco de dados e resolucao do adaptador de autenticacao.

Tópicos discutidos

  1. Atraso na integracao com a API de faturamento: Foi discutida a integracao com a API de faturamento do cliente, que travou devido a documentacao desatualizada em tres endpoints. A equipe descobriu o problema ao tentar autenticar e perceber que o endpoint de token nao existia mais, exigindo um novo formato de payload. O problema gerou retrabalho, fazendo a estimativa do adaptador subir de dois para cinco dias.
  2. Gargalo de desempenho no banco de dados: Foram apresentados os resultados dos testes de carga do banco de dados, que identificaram um gargalo na consulta de fechamento mensal, levando onze segundos para rodar devido a uma varredura completa na tabela de lançamentos. Foi aventada a alternativa de desnormalizar a tabela, mas a equipe optou por criar um índice composto na combinacao de cliente e data apos analise tecnica, descartando a desnormalização inicial.
  3. Readequacao do cronograma e cancelamento da demo: Devido ao atraso na integracao e a sobrecarga da arquiteta Beatriz, a equipe concluiu que a entrega prevista para a sexta-feira seguinte nao ocorreria. Apos proposta de Ana, o grupo decidiu adiar a entrega para o dia 28/08/2026, combinando a integracao e o desempenho. Ficou decidido tambem o cancelamento da demonstracao marcada para a sexta-feira, que sera remarcada junto com a nova data de entrega.
  4. Ambiente de homologacao separado: Carlos sugeriu a criacao de um ambiente de homologacao separado para evitar confusoes ocorridas nos testes feitos direto no ambiente de desenvolvimento. A ideia foi reconhecida como positiva, mas adiada para o proximo ciclo devido a custos de infraestrutura e falta de orcamento aprovado.

Decisões tomadas

  • Adiar a entrega para o dia 28/08/2026
  • Cancelar a demo de sexta e remarcar junto com a entrega

Outcomes da reunião

  • Entendimento compartilhado sobre as causas do atraso na integração, decorrentes de documentação desatualizada da API de faturamento do cliente.
  • Clareza obtida sobre o gargalo de desempenho na consulta de fechamento mensal, identificado como falta de índice adequado na tabela de lançamentos.
  • Alinhamento de que a entrega prevista para sexta-feira não ocorreria devido aos atrasos acumulados.
  • Entendimento compartilhado de que a proposta de ambiente de homologação separado não será implementada no momento atual por falta de orçamento aprovado.

Outputs da reunião

  • Lista dos três endpoints que mudaram na documentação da API de faturamento

Conclusão

A equipe avaliou os impactos do atraso na integração com a API do cliente e os gargalos de desempenho identificados nos testes de carga, decidindo por adiar a entrega do Projeto Fênix para o dia 28/08/2026 e cancelar a demonstração prevista para a sexta-feira ("Então proponho o seguinte: adiar a entrega para o dia 28/08/2026", "Só uma coisa. A gente precisa cancelar a demo que estava marcada pra sexta, senão o cliente aparece esperando ver o fluxo funcionando."). Como foco imediato, Beatriz criará o índice composto no banco de dados, Carlos finalizará o adaptador de autenticação e Ana comunicará oficialmente o adiamento ao cliente ("eu mando o comunicado do adiamento pro Rodrigo ainda hoje, a Beatriz cria o índice composto e roda os testes de carga de novo, e o Carlos fecha o adaptador de autenticação com o novo formato de token").
